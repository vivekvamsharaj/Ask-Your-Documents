# Ask Your Documents

A fully local RAG (Retrieval-Augmented Generation) app for asking natural-language
questions about your own documents. No external APIs, no data leaves your machine —
embeddings and answers are both generated by [Ollama](https://ollama.com) running
locally.

- **Upload** PDF, TXT, MD, or DOCX files
- **Ask** natural-language questions about them
- **Get** answers grounded only in your documents, with the exact source
  passages (document + page + relevance score) shown alongside every answer
- **Filter** questions to a single document, or search across your whole library
- **Stream** responses token-by-token, like a normal chat app

## Architecture

```
 React (Vite)                 FastAPI                    Ollama (local)
┌───────────────┐   HTTP    ┌───────────────┐   HTTP    ┌───────────────┐
│  Upload UI     │ ───────► │  /upload       │ ───────► │ embeddings     │
│  Chat UI       │          │   parse → chunk│           │ (nomic-embed-  │
│  Marginalia    │ ◄─────── │   → embed      │           │  text)         │
│  (citations)   │   SSE    │  /chat/stream  │ ───────► │ chat / generate │
└───────────────┘           │   embed query  │           │ (qwen2.5)      │
                             │   → retrieve   │           └───────────────┘
                             │   → generate   │
                             └───────┬────────┘
                                     │
                                     ▼
                              ┌───────────────┐
                              │ Chroma (local  │
                              │ on-disk vector │
                              │ store)         │
                              └───────────────┘
```

**Flow:**
1. A document is parsed into text (page-by-page for PDFs).
2. Text is split into overlapping chunks (~1000 chars, 150 char overlap) via a
   dependency-free recursive splitter (`backend/app/chunker.py`).
3. Each chunk is embedded locally by Ollama (`nomic-embed-text`) and stored in
   a persistent Chroma collection along with its source filename and page number.
4. On a question, the question itself is embedded, the top-k most similar
   chunks are retrieved, and those chunks are stuffed into a prompt sent to
   a local chat model (`qwen2.5`) which is instructed to answer **only** from
   the provided excerpts.
5. The answer streams back to the UI via Server-Sent Events, and the retrieved
   chunks are shown as citations ("marginalia") next to the answer.

## Prerequisites

- [Ollama](https://ollama.com) installed and running
- Python 3.10+
- Node.js 18+

Pull the two models used by default:

```bash
ollama pull qwen2.5
ollama pull nomic-embed-text
```

(`qwen2.5` generates answers; `nomic-embed-text` is a small, fast embedding
model — Ollama's chat models aren't embedding models, so a dedicated one is
needed for retrieval. You can swap either in `.env`.)

Make sure Ollama is running:

```bash
ollama serve
```

## Setup

### 1. Backend

```bash
cd backend
python3 -m venv venv
source venv/bin/activate        # Windows: venv\Scripts\activate
pip install -r requirements.txt
cp .env.example .env            # defaults already point at localhost:11434
uvicorn app.main:app --reload --port 8000
```

The API is now running at `http://localhost:8000`. Check `http://localhost:8000/health`.

### 2. Frontend

In a second terminal:

```bash
cd frontend
npm install
npm run dev
```

Open `http://localhost:5173`.

## Usage

1. Drop a PDF/TXT/MD/DOCX file into the sidebar — it's parsed, chunked, and
   embedded automatically.
2. Once it's indexed, ask a question in the chat box.
3. Click a document in the sidebar to restrict questions to just that file,
   or click it again to search your whole library.
4. Each answer shows the passages it was grounded in in the right-hand margin,
   with a relevance score.

## Configuration

All settings live in `backend/.env` (see `.env.example`):

| Variable | Default | Description |
|---|---|---|
| `OLLAMA_BASE_URL` | `http://localhost:11434` | Where Ollama is running |
| `EMBEDDING_MODEL` | `nomic-embed-text` | Model used to embed chunks/questions |
| `LLM_MODEL` | `qwen2.5` | Model used to generate answers |
| `CHUNK_SIZE` | `1000` | Max characters per chunk |
| `CHUNK_OVERLAP` | `150` | Overlap between adjacent chunks |
| `TOP_K` | `5` | Chunks retrieved per question |
| `CHROMA_PERSIST_DIR` | `./chroma_db` | Where the vector store is persisted |

## Notes on design choices

- **Why Chroma over FAISS/Pinecone?** Zero setup, persists to disk automatically,
  no external service or account — fits a fully-local stack.
- **Why a custom chunker instead of LangChain?** Keeps the dependency surface
  small and the retrieval logic transparent/inspectable for this challenge.
- **Why a separate embedding model from the chat model?** `qwen2.5` is a chat
  model, not an embedding model — Ollama needs a model specifically trained
  to produce embeddings (`nomic-embed-text`) for retrieval to work well.
